# 옛길 (Yetgil) — 디자인 판단 기준

> 이 문서는 "무엇을 만들지"가 아니라 **"왜 이렇게 만드는지"**를 적어둔 문서입니다.
> `app/lib/core/theme/`가 토큰(값)이라면, 이 문서는 그 토큰을 어떻게 조합해야
> "옛길답게" 보이는지에 대한 규칙입니다. 새 화면을 만들거나 AI에게 UI를 맡길 때
> 이 문서를 함께 넘기면 됩니다.

---

## 0. 우리가 지키는 4가지 원칙

토스·에어비앤비 같은 앱이 "같은 앱처럼" 느껴지는 이유는 화면마다 같은 판단 기준을
적용하기 때문입니다. 옛길은 아래 4가지를 판단 기준으로 삼습니다.

1. **가장 어두운 색은 검정이 아니다.** `#000000`을 쓰지 않는다. 본문 텍스트의 최대
   어두움은 `AppColors.ink` (`#1F1A16`) — 이미 지켜지고 있음. ✅
2. **강조색은 앱 전체에서 단 하나.** 나머지는 전부 무채색(베이지/그레이 톤)이다.
   → `AppColors.accent`. 색이 두 개 이상 경쟁하면 위계가 무너진다.
3. **그림자는 보이면 이미 과하다.** opacity 4~6% 이내, 카드가 "떠 있다"는 암시만
   준다 — 이미 지켜지고 있음 (`AppShadows`, 4%/6%). ✅
4. **숫자는 크게, 단위는 작게 — 2:1 비율.** 사용자의 시선이 숫자에 먼저 가야 하는
   화면(감성 점수, 연도, 소요 시간)에는 `AppTypography.statNumber`(48/700)와
   `statUnit`(24/400)을 짝으로 쓴다. → 지금까지는 없던 규칙, 이번에 추가.

## 1. 컬러 시스템

### 1.1 브랜드 컬러 갱신: 골드 → 브라운(`#6A452C`)

기존 포인트 컬러였던 골드(`#C2901E`, 앰버 계열)를 **브라운(`#6A452C`)** 으로 교체했습니다.
"옛길"이라는 이름 자체가 오래된 골목·빛바랜 사진·흙길을 떠올리게 하는데, 골드는
"화려함/고급 리조트" 톤에 가까웠고 브라운은 "손때 묻은 앨범, 오래된 나무 대문" 톤이라
브랜드 서사에 더 맞습니다. 채도도 낮아져서 원칙 2(강조색 단일화)가 더 명확해집니다.

| 토큰 (신규명) | 값 | 이전 이름 / 값 | 용도 |
|---|---|---|---|
| `AppColors.accent` | `#6A452C` | `gold` `#C2901E` | 유일한 강조색 — CTA 보더, 선택 상태, 비교 슬라이더 이음새(seam), 탭바 선택 아이콘 |
| `AppColors.accentTint` | `#EFE4D9` | `goldTint` `#F6EEDD` | 강조 아이콘/뱃지 배경 틴트 |
| `AppColors.accentDeep` | `#4A2F1D` | `goldDeep` `#8A5512` | 틴트 배경 위에 올라가는 텍스트/아이콘 (대비 확보) |

> 토큰 이름을 `gold*` → `accent*`로 바꾼 이유: 값이 브라운인데 이름이 "gold"면
> 다음에 코드를 보는 사람(혹은 AI)이 혼란스럽습니다. 의미론적 이름을 쓰면 나중에
> 브랜드 컬러가 또 바뀌어도 이름은 안 바뀝니다.

무채색 축(`paper`/`surface`/`fieldBg`/`ink`/`inkSecondary`/`inkTertiary`/`hairline`/`charcoal`)은
전부 기존 값 유지 — 이미 원칙 1·2를 만족하고 있었습니다.

### 1.2 사용 규칙

- `accent`는 반드시 "포인트"로만 쓴다. 배경 전체를 accent로 채우는 대형 서피스(예:
  풀블리드 배너, 큰 카드 배경)는 만들지 않는다 — CTA 버튼도 `ink` 채움을 유지하고
  accent는 보더·아이콘·언더라인 정도로만.
- 화면 하나에 accent가 등장하는 지점은 통상 1~3곳을 넘지 않는다. 4곳 이상 등장하면
  "강조"가 아니라 "장식"이 된 것 — 리뷰 시 체크.
- `accentTint` + `accentDeep` 조합(원형 배지, 필 뱃지)은 계속 써도 좋다 — 이미 코드
  전반에서 일관되게 쓰이고 있는 좋은 패턴 (아이콘 원, 연도 필 뱃지, 감성점수 뱃지 등).

## 2. 타이포그래피

기존 iOS 타입스케일(`largeTitle` 27/700 ~ `caption` 11/400)은 그대로 유지합니다.
이번에 추가하는 것은 **통계/숫자 강조용 페어**입니다.

| 토큰 | 크기/굵기 | 비율 | 용도 |
|---|---|---|---|
| `AppTypography.statNumber` | 48px / w700 | 2:1의 분자 | 감성 점수, 소요 시간 숫자, 연도 같은 "가장 먼저 봐야 하는 숫자" |
| `AppTypography.statUnit` | 24px / w400 | 2:1의 분모 | 그 숫자 옆/아래에 붙는 단위 텍스트 ("%", "시간", "년") |

**적용 원칙**: 숫자와 단위는 항상 이 2:1 비율 짝으로만 쓴다. 숫자만 크게 키우고 단위를
본문 크기로 두면 비율이 깨져서 "그냥 큰 글씨"가 되어버린다 — 반드시 짝으로.

**지금 바로 적용하면 좋은 자리** (코드는 아직 안 건드림, 다음 디자인 패스 후보):

- `CourseDetailScreen`의 "예상 소요 시간" — 현재는 `headline`(17px)로만 표시됨.
  숫자(예: `3`)를 `statNumber`, "시간"을 `statUnit`으로 분리하면 에어비앤비 평점
  숫자처럼 코스 상세의 "신뢰 신호"가 됨.
- `CourseListScreen`의 "감성 N%" 뱃지는 리스트 안의 작은 뱃지이므로 그대로 caption
  유지 (뱃지 안에서 48px는 과함). 대신 `CourseDetailScreen` 상단에 감성 점수를
  하나의 히어로 스탯으로 새로 보여주는 걸 고려 — 지금 상세 화면엔 점수가 아예
  없음(리스트에만 있음).

## 4. 카드 배치 & 화면 리듬

### 4.1 "같은 레이아웃을 연속으로 두 번 쓰지 않는다"의 의미

이 규칙은 **한 화면 안에서 서로 다른 성격의 섹션**이 연달아 나올 때 적용됩니다.
**같은 종류의 데이터를 나열하는 리스트**(뉴스 타임라인, 코스 목록)는 원래 반복되는
게 맞습니다 — 리스트 안에서 매 항목마다 다른 레이아웃을 쓰면 오히려 스캔하기
어려워집니다. 규칙은 "리스트 아이템끼리 다양하게"가 아니라 **"섹션과 섹션 사이에
변주를 준다"** 입니다.

### 4.2 현재 화면별 리듬 진단

| 화면 | 섹션 구성 (위→아래) | 진단 |
|---|---|---|
| **홈(추억)** | 입력 카드(단일 큰 카드) → 4분할 숏컷 그리드 → 가로 스크롤 카드 리스트 → 아이콘+텍스트 배너 | ✅ 4개 섹션이 전부 다른 모양. 이미 리듬이 좋음 — 새 섹션을 추가할 땐 이 4개와 겹치지 않는 5번째 모양(예: 통계 스트립)을 쓸 것. |
| **비교(compare)** | 타이틀 → 히어로(슬라이더, 이미지 기반) → 안내 문구 → 본문 텍스트 | ✅ 카드가 거의 없고 히어로 하나에 집중 — 시그니처 기능이니 이게 맞음. 여기에 카드를 더 추가해서 산만하게 만들지 말 것. |
| **아카이브(뉴스)** | 동일 형태 타임라인 카드 반복 | ✅ 리스트 화면이라 반복이 맞음. 다만 상단에 "이 지역 뉴스 N건" 같은 요약 스탯 한 줄을 추가하면 리스트 진입 전 맥락을 줄 수 있음 (§2의 statNumber 후보). |
| **코스 리스트** | 동일 형태 코스 카드 반복 | ✅ 위와 동일 진단. |
| **코스 상세** | 타이틀+설명(텍스트) → 방문 순서 카드(넘버링 리스트+구분선+요약행) | ⚠️ 섹션이 2개뿐이라 단조로울 수 있음. 감성 점수 히어로 스탯(§2)을 타이틀 아래에 추가하면 텍스트 → 스탯 → 카드 3단 리듬이 생김. |
| **프로필** | 스캐폴딩만 존재 | ❌ 콘텐츠 설계 필요 — 아래 §4.3 참고. |

### 4.3 새 섹션을 추가할 때 고르는 법

아래 "모양 팔레트"에서 **이미 위/아래에 쓰인 것과 다른 모양**을 고릅니다.

- **히어로**: 화면에 하나만, 이미지·슬라이더처럼 화면 폭 전체를 씀 (예: 비교 슬라이더)
- **그리드**: 동일 크기 타일 N개, 정사각형에 가까움 (예: 홈의 4분할 숏컷)
- **가로 스크롤 리스트**: 카드가 옆으로 흐름, 화면 폭보다 좁은 카드 (예: 최근 골목)
- **세로 리스트**: 카드가 아래로 쌓임, 화면 폭 전체 (예: 뉴스/코스 리스트)
- **배너/행(row)**: 아이콘 + 텍스트 2줄 + 화살표, 높이가 낮음 (예: 추천 배너)
- **스탯**: `statNumber`+`statUnit` 페어, 카드 없이 텍스트만 (신규)

같은 화면에 이 팔레트 중 하나를 두 번 이상 연속으로 쓰지 않는 게 목표입니다.

### 4.4 프로필 화면 설계 제안 (콘텐츠 없음 — 다음 작업 후보)

현재 스캐폴딩만 있는 상태입니다. 위 팔레트를 적용하면:

1. **배너**(현재 계정 요약: 이름/한 줄 소개) → 2. **스탯**(둘러본 골목 수, 저장한
코스 수 — statNumber/statUnit 페어로 2개 나란히) → 3. **세로 리스트**(설정 메뉴:
알림/약관/로그아웃). 3단 리듬으로 §4.2의 다른 화면들과 톤이 맞습니다.

## 5. 금지 패턴 체크리스트

새 화면/컴포넌트를 리뷰할 때 아래에 걸리면 되돌립니다.

- [ ] `Color(0xFF000000)` 또는 `Colors.black`을 텍스트/배경에 직접 쓰지 않았는가 → `AppColors.ink` 사용
- [ ] accent 계열 색(`accent`/`accentTint`/`accentDeep`)이 한 화면에 4곳 넘게 쓰이지 않았는가
- [ ] 그림자를 `AppShadows.card`/`.tile` 대신 직접 만들지 않았는가 (opacity 10% 넘는 임의 그림자 금지)
- [ ] 큰 숫자를 보여줄 때 단위 없이 숫자만 덩그러니 두지 않았는가 (statNumber는 항상 statUnit과 짝)
- [ ] 한 화면에서 같은 "모양 팔레트"(§4.3)가 3번 연속 나오지 않는가
- [ ] 라운딩 값을 `AppRadius` 대신 매직넘버로 쓰지 않았는가
