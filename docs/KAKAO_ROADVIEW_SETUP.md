# 카카오 로드뷰 — 설정 가이드

코드는 다 준비됐습니다: 백엔드가 `GET /roadview/{location_id}`로 완결된 HTML(카카오맵
JS SDK + Roadview)을 서빙하고, 앱은 `webview_flutter`로 그 페이지를 그대로 띄웁니다
(비교 슬라이더는 그대로 두고, "지금 이 거리, 실시간 로드뷰로 보기" 버튼을 눌러야 뜨는
별도 패널 — PROJECT_BRIEF.md의 "로드뷰는 선택적 WebView 패널" 설계 그대로).

## 지금 막혀 있는 것

방금 실제 키로 테스트해보니 카카오 로컬 API가 이 에러를 반환했습니다:
```
"App(...) disabled OPEN_MAP_AND_LOCAL service."
```

**Kakao Developers 콘솔 → 내 애플리케이션 → 제품 설정 → 카카오맵** 에서 활성화 ON 해주세요.
(카카오 로그인처럼 앱 키만으로는 안 되고 제품별로 따로 켜야 합니다.)

## 도메인 등록도 필요합니다

카카오맵 JS SDK는 **로드된 페이지의 도메인**을 콘솔에 등록된 플랫폼과 대조합니다.
이 로드뷰 페이지는 우리 백엔드가 서빙하므로, **백엔드가 실제로 떠 있는 주소**를
카카오 콘솔 **플랫폼 → Web**에 등록해야 합니다.

- 로컬 개발 중 실기기로 테스트한다면: 개발 PC의 LAN IP (예: `http://192.168.0.5:8000`)
  → `flutter run --dart-define=API_BASE_URL=http://192.168.0.5:8000 ...`로 앱을 띄우고,
  같은 주소를 카카오 콘솔에 등록
- 에뮬레이터로 테스트한다면: `http://10.0.2.2:8000` (에뮬레이터에서 호스트 PC를 가리키는 특수 주소)
- 나중에 오라클 클라우드에 배포하면: 그때의 Public IP 또는 도메인으로 다시 등록

## 확인 순서

1. 카카오 콘솔에서 카카오맵 활성화
2. 위 도메인 등록
3. 백엔드 재시작 없이 바로 확인 가능:
   ```bash
   curl http://<백엔드_주소>:8000/roadview/suncheon-jeonpo
   ```
   HTML 안에 `kakao.maps.Roadview`와 실제 좌표 숫자가 보이면 좌표 찾기까지는 성공한 것.
   (좌표를 못 찾으면 `"...의 위치를 찾지 못했어요"` 메시지 페이지가 뜹니다 — 이건 정상
   폴백이고, 1단계 활성화가 안 된 상태에서 항상 이렇게 나옵니다.)
4. 앱에서 아무 장소의 비교 화면 → "지금 이 거리, 실시간 로드뷰로 보기" 버튼 클릭.
   실기기 브라우저 대신 앱 안 WebView에서 떠야 도메인 등록이 제대로 된 것.

## 알려진 한계 (정상 동작)

- 카카오 로드뷰는 **커버리지가 있는 곳에서만** 나옵니다. 좌표는 찾았는데 그 근처에
  로드뷰 촬영 데이터가 없으면(주로 인구감소지역/외곽) "이 지역은 아직 로드뷰가
  제공되지 않아요" 메시지가 뜨는데, 이건 버그가 아니라 실제 커버리지 한계입니다.
- 로드뷰는 항상 **현재** 모습만 보여줍니다. "과거" 비교는 여전히 큐레이션한 정적
  이미지(`CompareSlider`) 몫이고, 로드뷰는 그 옆에 "지금 실시간으로 보면 이렇다"를
  더해주는 보조 기능입니다.
